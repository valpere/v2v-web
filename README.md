# v2v-web — веб-фронтенд голосового/текстового AI-асистента

Звичайна веб-сторінка для рушія [v2v-demo](https://github.com/valpere/v2v-demo):
вибір теми, розмова, кошик. Маленький Go-сервер віддає сторінку і пересилає `/v1`
до рушія; логіка розмови, каталог, кошик і ціни — у рушії.

**Статус:** перший каркас; текстовий режим; ще не розгорнуто. Що далі — [`docs/HANDOFF.md`](docs/HANDOFF.md).

## Як це влаштовано

```
браузер ──► v2v-web (статика + проксі /v1) ──► рушій (v2v-demo, WEB_ADDR)
```

Браузер не має Telegram `initData`, тому сервер сам «поручається» за відвідувача:
дає йому анонімний ідентифікатор (HttpOnly-cookie) і передає рушію
`X-Principal` із спільним секретом. Клієнт не може обрати чужий ідентифікатор.

Інші фронтенди того ж рушія: [v2v-bot](https://github.com/valpere/v2v-bot) (Telegram),
[v2v-tma](https://github.com/valpere/v2v-tma) (Telegram Mini App).

## Запуск

```bash
# рушій (v2v-demo): WEB_ADDR=127.0.0.1:8091 WEB_TRUSTED_KEY=<той самий, що ENGINE_KEY>
cp .env.example .env   # ENGINE_URL, ENGINE_KEY
make run               # http://127.0.0.1:8086
make check             # gofmt, vet, тести з -race, node --check, збірка
```

| Змінна | Призначення |
|---|---|
| `ENGINE_URL` | базовий URL `/v1` рушія (обов'язково) |
| `ENGINE_KEY` | спільний секрет довіреного фронтенда (= `WEB_TRUSTED_KEY` рушія, ≥ 32 символи); порожній = пересилати як є (рушій із `WEB_DEV_AUTH=1`, лише локально) |
| `ADDR` (`127.0.0.1:8086`), `WEB_DIR` (`web`) | |
| `TRUST_PROXY=1` | брати адресу клієнта з `X-Forwarded-For` (лише за власним reverse proxy) |
| `PUBLIC_ORIGIN` | власний origin сайту (`https://demo.example`): CSRF-перевірка `Origin` точно за ним, HSTS; обов'язково за proxy, що міняє `Host` |

**Ліміти** (в пам'яті, `internal/server/limits.go`; перевищення — `429` + `Retry-After`): повідомлення — на відвідувача 6/хв і 60/добу, на IP 12/хв і 120/добу, весь сайт 150/добу (за Києвом); нові розмови — 10/год на відвідувача, 20/год на IP. Це окремо від лімітів рушія.
